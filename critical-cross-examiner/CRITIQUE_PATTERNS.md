# Critique Patterns

Canonical repository of recurring failure patterns and required planning checks.

Use this file as the source of truth for reusable critique guardrails.

## Promotion Rules

1. Promote from `OPEN_QUESTIONS.md` only when a pattern repeats or has high impact.
2. Add each promoted pattern as a checklist item with:
   - Pattern
   - Trigger
   - Required Check
   - Evidence Signal
3. Include a rationale in the commit message body:
   - `Rationale: promote recurring failure pattern <id>`
   - `Evidence: <refs to OPEN_QUESTIONS entries or incidents>`
4. Keep promotions atomic: one pattern change per commit when practical.
